# Portability Acceptance Standard

A new real deep-tech target passes the pack only when all ten gates pass:

```text
New human-selected deep-tech target
→ exact selection receipt
→ zero target-specific code changes
→ bounded public acquisition receipts
→ strict governed state
→ sector transfer controls applied
→ Public Baseline + Diligence Map + Admission Map + Operating Readiness compile
→ technical-readiness gaps remain explicit
→ deterministic release rebuild
→ one later material public event compiles as a bounded successor delta
→ private state and external effects remain absent
```

## Failure conditions

A portability attempt fails if any target name, target-specific state transition, source URL, or special-case business rule must be added to generic code to make the target fit. The remedy is to either express the need as a reusable schema/policy rule or classify the target as outside the pack.

A target also fails if a public statement is promoted into a private instrument, legal conclusion, funding receipt, customer, procurement state, technical qualification, IP title, delegated authority, production state, or deployment without the evidence class required by the corresponding transfer control.

## Reference discipline

Reference fixtures may contain real target names and facts. Generic code, schemas, templates, and policy rules may not. Synthetic fixtures may exercise edge cases without becoming target-selection substitutes.

## Terminal states

- `PASS_PORTABLE`: all gates pass with zero target-specific code changes.
- `HOLD_EVIDENCE`: the pack fits, but one or more target facts remain unresolved.
- `HOLD_SECTOR`: a required sector rule is missing and must be generalized before continuing.
- `FAIL_TARGET_SPECIAL_CASE`: the implementation depends on target-specific code.
- `FAIL_BOUNDARY`: private state or an external effect entered the public-only lane.

## Executable portability battery

The portability gate is tested against four synthetic startup shapes using the same compiler. The validator requires all four to produce the same four governed outputs, requires each admission map to retain company-controlled gaps, freezes each fixture twice and compares archive bytes, and applies one material successor event against a known prior state. This battery demonstrates implementation portability. It does not substitute for a human-selected real Target 02.
