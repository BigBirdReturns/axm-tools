What stays under your control

Signed packages identify content and a publisher key. Each recipient decides which publishers may run which applications. Package import starts no code. A backup carries selected and prior code plus persistent application data; restore leaves the application stopped and keeps the new operator's identity. Exported evidence preserves the old operator's signed history for independent verification. It does not merge that history into the recipient's active database.

The controller has no required hosted control service or account. The application you choose can still require a Python runtime, libraries, hardware or an external API. Its prerequisites remain part of its operating contract.

Platform and recovery boundaries

The Linux executable requires x86_64 and glibc 2.43. Source installation uses Python 3.11 or newer with compatible locked dependencies. The native Windows controller was qualified on Windows 11. macOS has no released binary or recorded qualification. The SSH adapter targets a POSIX recipient shell.

Services survive console and submitting-client closure while their machine keeps running. Starting services after a reboot requires explicit action or separately configured OS supervision. Service updates use a restart transition. Code rollback keeps current application data, including candidate writes. Applications own data migration, external transaction consistency and the meaning of their output.

Programs execute with the operator account's access. Signed history supports verification of keys, content and recorded ordering; it does not establish physical hardware identity, external factual truth or correct behavior by a compromised signing host.
