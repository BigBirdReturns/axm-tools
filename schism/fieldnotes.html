Fieldnotes keeps project notes, procedures, meeting records and other text on your computer. Search titles, text and tags; import UTF-8 text or Markdown; download a note as plain text or export the whole notebook. Version 1.1 adds pinned notes while keeping the same portable data format as version 1.0.

1. Extract both downloads

Install Python 3.11 or newer. Extract the complete SCHISM source ZIP and Fieldnotes ZIP into the same parent directory. The controller folder contains schism.py; the application folder contains open-fieldnotes.py. Keep both folders intact.

The commands below assume the extracted folders are named schism-stack and fieldnotes. Open a terminal inside fieldnotes. If you choose different locations, replace ../schism-stack with the path to your controller folder.

2. Open the notebook

On Windows:

py -3 open-fieldnotes.py --schism ../schism-stack

On Linux:

python3 open-fieldnotes.py --schism ../schism-stack

The launcher prepares SCHISM's isolated runtime, packages the included Fieldnotes source with your operator identity and starts it. It opens a private browser link at 127.0.0.1:8787. First setup downloads the controller's hash-locked dependencies; a compatible offline wheel kit also works. Fieldnotes itself uses Python's standard library and makes no external service requests.

You can also pass the path to a complete SCHISM 0.1.1 native distribution or its controller executable. The notebook still requires Python 3.11 or newer on PATH. Windows and Linux are the qualified routes. This application release claims no macOS qualification.

You hold the application and the data. Your default operator state is ~/.schism; the launcher prints the exact notes directory and private link. Add --state /path/to/private-state to use a separate operator. The launcher signs its included source with your key and adds no publisher trust grants.

3. Keep something useful

Select New note, write a title and text, add tags if useful, then select Save note. Search checks saved titles, bodies and tags. Import text opens a UTF-8 text or Markdown file as a draft. Save the draft to keep it. Download text exports the selected saved note; Export notebook downloads the saved collection. Save your edits before exporting.

Notes are ordinary UTF-8 JSON files with a documented schema, and the export also includes plain-text copies. The browser displays text as text. You can archive and restore notes; version 1.1 also pins frequently used notes. A stale edit from another tab is refused so you can preserve your draft before loading the newer saved version.

Closing the browser leaves the service running. Run the same launcher again to reopen it. To stop the service, repeat the launch command with --stop. Your notes remain on disk. Each service start creates a new private browser token, so use the newly printed link after restarting or changing versions.

4. See what survives an update

The kit includes both complete releases. To exercise the version transition, add --app-version 1.0.0 to the launch command and save a note. Then use --app-version 1.1.0. The same notebook opens with the pinning feature available. Edit and save the note, then use --rollback to restore version 1.0.

The earlier code opens your latest notes. Both releases declare the same data schema, so code rollback retains current text, tags and the compatible pin field. The controller restarts the service during each transition. This example establishes continuity for this notebook's format; another application's data migration needs its own acceptance.

5. Hand it to another operator

Use the PowerShell command prefix or Shell command prefix printed by the Fieldnotes helper for SCHISM commands. It selects the controller and your chosen private state. The complete application README gives the exact backup, verification and authorization steps.

  1. Stop Fieldnotes. Add --stop to its launch command. Create the stopped-application backup, then export the operator's signed evidence separately.
  2. Carry both files. The backup contains selected and prior application code plus the notes. The evidence export preserves the earlier operator's signed operating record. Establish the signer's fingerprint through an independently trusted channel.
  3. Restore into a fresh operator state. The recipient verifies the backup and old evidence against that fingerprint. The restored application remains stopped under the recipient's own identity.
  4. Authorize and continue. The recipient grants the verified publisher authority for fieldnotes, then starts the restored service. Its new history records the backup it restored; the original signed history remains independently verifiable.

The application helper's normal open command starts an already selected notebook; it adds no foreign publisher grant. Use the explicit authorization step for a restored package from another operator.

Operating details

Fieldnotes binds only numeric loopback on port 8787 and requires a private token for notebook reads, edits and exports. One Fieldnotes instance uses that port; stop it before opening a different --state notebook. Keep the printed link private. The notes and exported files are plaintext and use your OS account's filesystem protection. A backup carries note contents, so handle it as you would the notebook itself.

The application runs under your account and keeps a single saved notebook format. It provides local writing, search and export; simultaneous saves use note revisions to refuse stale edits. There is no cloud synchronization or multi-user sharing service. Reboot startup requires explicit action or separately configured OS supervision.
