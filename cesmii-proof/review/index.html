Architecture

A receiving team recomputes the record

The source adapter retains endpoint, method, request, response bytes and observation time. The workflow engine uses explicit fields and rules to calculate a conclusion against exact source revisions. A correction changes the current evidence frontier while preserving previous decisions.

Source-to-receiver flow

i3X source context

Discovered object IDs, raw read responses, quality and timestamps

Workflow evidence

Owner labels, observed values, explicit rules and source corrections

→

The complete record travels with the result. Each recipient can check the calculation without access to the originating browser or AXM-hosted service.

Member workflow

Supply an ordinary maintenance handoff

A de-identified workflow is a concrete operational decision with its required inputs and one later correction. An organization can replace equipment, work-order and personnel identifiers with consistent aliases while preserving the relationships and quantities needed to reproduce the decision.

Example provided in this package

A maintenance task requires one serviceable seal. Inventory records two serviceable seals and planning records two already allocated. The available quantity is zero. A corrected allocation of one leaves one available seal, which changes the parts conclusion while preserving the original shortage.

The template also checks whether planned maintenance duration fits the stated window and whether the declared procedure allows planning. These are record-based checks on supplied inputs.

Download the editable workflow JSON →

What a member supplies

  • A consistent equipment alias and its selected i3X object ID.
  • Required part quantity, serviceable stock and existing allocations.
  • Source labels and observation times for the contributing teams.
  • The applicable procedure and planning window.
  • A correction with its predecessor and reason, followed by a receiving team's replay.

The supplied template is synthetic. Member data receives its own evidence class; the local application does not upload it.

Customer names, staff names, site addresses, credentials and unrestricted raw exports are unnecessary for this example. Keep any private alias lookup with the contributing organization. The useful result is the preserved relationship among the records, the rule and the changed conclusion.

Browser review

  1. Open the member workbench and load the included example or import the workflow template.
  2. Select the retained public i3X observation, import a capture file, or read an explicitly configured endpoint.
  3. Evaluate the workflow and inspect the rule results and source dependencies.
  4. Correct the allocation from two to one. Inspect the prior conclusion's stale standing, then evaluate again.
  5. Export the capsule. Open a clean browser or the offline client, import it and inspect the reconstructed history.

Inspect execution evidence

Evidence and authority. Public reference data, synthetic examples and operator-supplied records carry distinct evidence classes. “Current” means consistent with the selected retained inputs; freshness is assessed at the recorded evaluation time under the declared policy. Source authenticity, physical condition, real user identity and permission to perform maintenance remain with the contributing organization. This application prepares and verifies decisions; it sends no equipment commands.
