Second Run turns a resolved judgment into a procedure another person can inspect and repeat. Each result carries the inputs, assumptions and procedure that produced it. On the next request, Second Run checks those dependencies, reuses the results that still hold and executes the affected work.

What stayed the same in the evaluation?

The Run 3 A/T0 calculation joined retained grading results to 8,622 completed requests. It counted 4,336 accepted under the recorded rule. Its input identity and result checksum stayed identical across all three requests. The price scenario applied only to the Latitude offer calculation. All three requests used zero new GPU runs and zero model calls.

What qualifies a result for reuse?

The runner keys a task by its class, semantic parameters, runtime versions and the bytes of declared inputs and procedures. It checks dependencies and the stored result checksum on reuse. A change to a shared input file can invalidate several calculations. A reused listing keeps its original observation date and holds.

Where the work repeats

Software workflows

Capture a validation procedure with its inputs and acceptance rule. The next operator can inspect the result and determine which checks a change affects.

Media production

Record which source, edit decisions and delivery settings a derivative depends on. A revision can then identify the outputs that require another production pass.

Technical investigation

Retain the source observations, calculation and unresolved questions behind a conclusion. A revised assumption can travel through the dependent work with its provenance intact.

Reproduce the three requests

Download the replay script beside a clean checkout of the public Cantos source. With Git, Python 3.12 or newer and Node.js 22 or newer on your path, run these commands from the download directory.

Download replay.py

git clone https://github.com/BigBirdReturns/cantos.git
git -C cantos checkout --detach 0c9594b4d0c302e5b6da41f32fb983256c0e1391
python replay.py cantos

The script creates a new local result directory and prints three receipt paths. Open any receipt to inspect task status, dependency keys and result hashes. The six-task workflow runs locally using committed fixtures. Cloning the public source is the only step that needs network access.
