# The Estate action case study

This page turns the Estate's recorded policy and execution history into an authored, interactive action study. It is a real operational analogue of inherited supply-chain decisions, not customer data or proof of enterprise-wide deployment.

The reviewed native recorder snapshot contains 29,804 source versions, 20,827 distinct objects, 6,626 parsed native jobs, 43 relevant Git changes, 26 original policy sections, 570 migration changes and 555 unique reset targets. The whole-corpus integrity check rehashed all 20,827 stored objects. A separate native source check revalidated 30 located references across ten source-linked decision chains with zero hash failures. These checks establish retained byte integrity, not original truth, historical completeness or causation.

The public page preserves original purpose, inherited mechanism, recorded consequence, historical intervention, retained obligation and proposed next action. Its three deterministic replays cover completion reporting, assumed repeated input and versioned prompt totals. Its local JSON export is explicitly PROPOSED, carries source digests, owner role, preserved constraints and an acceptance test, and has no approval or execution receipt.

## Findings

Authorizing the individual choices did not make their combined effects visible. The case shows a coordination failure within a single-owner system; competing departmental incentives are not required to produce this mechanism. This inference does not establish enterprise prevalence.

The central policy shrank from 45,918 to 5,755 bytes, an 87.4668% reduction. This measures repeated-input payload, not task speed or financial savings. The old launcher returned process success despite W01 inner exit 1 and N01 inner exit -9. The corrected proof maps completed to 0 and both usage_meter_unavailable and failed to 1. Reporting improved; missing-usage workload acceptance remains a separate obligation.

The spending guard had a documented purpose and a measured enforcement boundary: a 60,000-token stopping threshold was observed at 83,374 tokens, including 62,976 cached input tokens. A later W01 cold entry recorded 62.36 seconds, zero usage records and zero tool calls. Preserving that history supports a compatibility repair without silently erasing spending protections.

Migration counters recorded 296 GB of rehash work at 10:14; the controller recorded a 09:27 start and 10:26 operator stop after earlier acceptance evidence. The 59-minute interval is observed elapsed time, not a general savings estimate. Queue classifications of 826,726 regenerable artifacts among 2,188,321 small files come from the retained controller report, not a newly inspected original queue.

Eight prompts changed while ten tasks were active. The eight apply receipts total 97,304 -> 39,829 characters. A later readback totals 42,095 after a concurrent owner update. Different populations and observation times remain explicit rather than being presented as contradictory truth.

## Use and boundaries

Open index.html independently or through the hosted route. Select any of ten histories. Inspect its source locator, test the replay and export a proposed change. The study makes no external application requests; reviewer notes remain in the current browser and chosen download. No operational changes or hidden workers are started.

The private recorder and raw source corpus are not published. case-data.json contains public-safe summaries, measurements and source locators. One of 22 declared historical receipt digests is absent from the admitted corpus. First retained versions are not necessarily the first-ever authoring events. The observation set is a retrospective snapshot, not a permanent recorder service.
