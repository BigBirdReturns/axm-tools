# Decision Floor 0.2 | Acceptance boundaries

This release is an independent, customer-run evaluation package. It does not include or claim any private Aankhen code, infrastructure, internal CI specifications, fiChains connection, credential or dataset. The visual design uses the green/white tone observed on Aankhen's public website, with no vendor font dependencies or Aankhen trademark/logo implying endorsement.

**Behavioral acceptance:** a new authorized decision updates the target while retaining the earlier plan; independent ERP, PO and MES events determine whether implementation occurred; missing receipts stay missing; late convergence retains its delay; warehouse value is calculated only from recorded quantity, target and cost basis; original statements are indexed and preserved as statements; source hashes/row locators allow independent inspection; observed conflicts are not silently selected as truth; manual reviewer notes do not overwrite the machine's findings.

**Data custody:** all source bytes are archived under SHA-256 locally, with SQLite index and no third-party packages required for the core. Browser calls reach only the same-machine 127.0.0.1 service. New uploads with the same filename are scanned into the evidence vault before replacing the landing file. Token required on API requests, API origins checked where available, malformed filenames and mapping traversal refused. Original systems remain untouched. This is not equivalent to enterprise security certification.

**Qualification:** the public `data/qualification.json` is produced by freshly extracting and testing the downloadable distribution. Historical screenshots are not bundled as current acceptance. `qualify.py` reruns manifest, unit/integration, and seeded novel-case validation from an extracted ZIP. `python -m unittest discover -s tests -v` covers source fidelity, missing documents, bitemporal as-of, unauthorized approval, conflict, tamper checks and a complete local HTTP API sequence. `python tools/novel_case_oracle.py --cases 1000 --seed 931527` independently checks operational state and outcomes on genuinely generated new synthetic records with socket creation blocked. The standalone browser check uses fixture-backed Chromium because the testing environment restricts direct local-browser navigation; HTTP behavior is separately exercised through real loopback Python client tests. Neither check represents a qualified live customer ERP integration.

**Not yet qualified:** vendor-specific native ERP/MES adapters, real corporate mailbox access, enterprise ACL/SSO, autonomous free-form semantic investigation, scanned PDF OCR, source creation-time attestation, very high volume ingest in live customer systems, causal attribution of inventory cost to a particular person, human authorization of decisions and deployment to Aankhen's actual internal environment.
