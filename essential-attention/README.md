# Essential Attention: FAB Offer Register and Executive Review

Essential Attention is a local-first administrative case runtime. Version 1.0.4 opens with one populated cartridge, `mw-ea-n0-fab-offers-001`, which reconstructs the aftermath of the first Futures Advisory Board meeting as a source-linked set of events, offers, open questions, decisions, and continuity obligations.

The page is not a generic dashboard and it is not a task assignment system. It is the working case file for one bounded administrative object. It keeps the available evidence, the current interpretation of each item, the authority actually held, the next safe internal action, and the external effect still withheld in one portable browser surface.

## Open the application

The hosted application is available at:

`https://bigbirdreturns.github.io/axm-tools/essential-attention/`

The committed `index.html` is also the offline application. It contains the interface, the public-safe FAB cartridge, the contained role logic, local persistence, import and export, and the qualification boundary in one file.

## What loads when the page opens

The default FAB cartridge contains seven case objects:

| Object | What it represents | Current state |
|---|---|---|
| FAB advisory service | The accepted quarterly advisory role and its limits | Accepted |
| FAB Meeting #1 | The completed July 30, 2026 advisory meeting | Completed |
| FAB Meeting #2 scheduling | Tentative October scheduling options that have not become an authoritative invitation | Held |
| Unnamed Meeting #1 offers | An aggregate reference to projects, connections, and resources whose literal actors and terms are not yet recovered | Mentioned |
| Survival-radius and repeated-void method | A bounded analytical review method accepted for source-grounded use | Accepted |
| Catnip, nursery, and field bridge | A conditional future review offer that must remain dormant until a concrete source packet and question exist | Offered |
| Essential Attention N=0 runtime | The internal system objective to carry the clerical and continuity work without assigning a person as the runtime | Accepted |

The cartridge also contains five bounded decision objects:

1. Set the Meeting #2 scheduling disposition.
2. Recover or expire unnamed post-meeting offers.
3. Bound the Catnip and field-bridge review.
4. Operate Essential Attention as the N=0 internal runtime.
5. Define the external-effect authority map.

It further contains five public-safe source summaries, seven functional seats, a bounded FAB review question, a successor replay packet, an effect firewall, and an append-only local ledger.

## What the application does

Inside the browser, the application can:

- show the seven case objects and their source-linked current states;
- distinguish an event, mention, conditional offer, accepted review, and completed action;
- present only the five questions elevated for bounded executive attention;
- record local draft dispositions without making an official decision;
- run the contained source, interpretation, relationship, attention, execution, verification, and continuity functions;
- hash private source files locally and create SHA-256 source receipts;
- test whether a cold successor can reconstruct the case from durable records;
- test an external-effect request against evidence, authority, purpose, consequence, conflict, and continuity;
- export the complete cartridge and local case state as a portable JSON packet;
- download the current application as a standalone offline HTML file.

## What the application does not do

The application has no adapter for email, calendar changes, payment, publication, institutional acceptance, appointment, or representation. Opening the page, choosing a local disposition, running the contained seats, or exporting a packet does not contact anyone or bind any person or organization.

A real authority is required only when a specific action crosses the external-effect boundary. The browser may prepare the packet for that action, but it cannot release the action itself.

## First use

A first-time browser opens an orientation dialog. The same explanation is always available through the **Help** button and the **Start here** view.

The recommended route is:

1. Open **Case register** and inspect all seven objects. For each object, read the literal event or offer, current state, authority, scope, next safe state, fallback, and source receipts.
2. Open **Decisions** and inspect the five bounded questions. A disposition button creates a local draft receipt only. It does not perform the external act described by the decision.
3. Open **Internal run** and select **Run all contained seats**. The run tests whether the internal administrative functions can complete without locating seven people.
4. Open **Handoff test** and use the displayed successor packet to answer the four replay fields. A passing replay shows that the current case can be reconstructed from durable records.
5. Open **Sources** only when a private file is relevant. The browser reads the file locally, computes a SHA-256 digest, and stores source metadata. The file bytes are not transmitted or retained by the page.
6. Open **Activity & export** and export the portable packet. The exported packet is the durable handoff for another browser, offline copy, or successor.

The **Take the guided tour** control performs this route one view at a time and explains what to look for at each step.

## Vocabulary

**Object** means one event, offer, unresolved possibility, decision dependency, or system commitment that the case must preserve, resolve, monitor, or prepare.

**State** means what the available evidence currently supports. Examples include mentioned, offered, accepted, held, and completed.

**Seat** means a required function with defined information needs and authority limits. A seat is not a named person. A contained browser process can exercise a seat for internal qualification.

**Receipt** means a local, timestamped record of a source hash, interpretation, disposition, contained run, firewall result, replay, import, or export.

**External effect** means an act that changes the outside world, such as sending, scheduling, paying, publishing, accepting, appointing, or representing.

**Cartridge** means the domain and case-specific vocabulary, objects, aliases, sources, decisions, and presentation loaded into the reusable runtime.

## Data custody and persistence

The application is served from a public GitHub Pages origin, but the committed page contains only the public-safe cartridge. Any private file selected in **Sources** is read locally by the browser. The page computes its digest and stores only the receipt metadata. It does not make a network request and it does not retain the source bytes.

Local state is stored in IndexedDB when available, with a localStorage fallback. State is scoped to the browser profile and the hosted origin. It does not automatically synchronize across devices or browser profiles.

A meaningful session should end with a portable packet export. The packet contains the active cartridge, local ledger, local source receipts, contained-seat runs, and an integrity digest. Importing that packet into another copy of the page restores the portable case state.

Clearing local state removes local drafts, source receipts, contained runs, imported cartridges, and onboarding state from that browser. It does not alter the embedded FAB cartridge in the committed application.

## Public and private boundaries

The public cartridge preserves source descriptions and case structure without publishing private source bytes. Private source material should enter only through local intake unless an authorized public release has been deliberately prepared.

An imported cartridge or packet is accepted only when it contains the required object, decision, role-profile, and source arrays. Importing a packet changes only the local browser state. It does not alter the GitHub Pages application or any external system.

## White-label architecture

The reusable runtime operates on goals, objects, source receipts, role profiles, decisions, authority, purpose, consequence, receipts, and replay. The FAB cartridge supplies the local vocabulary, seven objects, five decisions, aliases, public-safe source summaries, and visual emphasis.

A later cartridge can replace the FAB vocabulary and case data while retaining the same source custody, force preservation, effect boundary, local ledger, export, and continuity mechanisms. The current release proves one populated case. It does not yet prove every future domain.

## Qualification

`QUALIFICATION.json` records the static qualification of the committed standalone page. The public contract test verifies the orientation surface, help dialog, guided tour, seven case objects, five decisions, seven contained roles, source boundary, effect firewall, successor replay, one-file structure, and absence of the earlier compressed loader.

The browser harness verifies the first-run help experience, guided-view transitions, contained-seat run, external-effect block, successor replay, local persistence, mobile overflow, and absence of network requests outside the local test origin.

## What can rot

Browser support for IndexedDB, Web Crypto, file input, Blob downloads, the `<dialog>` element, and the current Content Security Policy behavior can change. GitHub Pages or the repository deployment workflow can also change.

A failure must remain visible. The application must never silently upload a source, infer authority, promote the force of an offer, claim an external action occurred, or discard a local receipt because a browser feature is unavailable.
