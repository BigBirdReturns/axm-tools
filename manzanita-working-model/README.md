# Manzanita Works Working Model v1.0.0 candidate

This surface is the convergence layer for the Manzanita estate. It exists because the underlying system became substantially more complete than the ordinary explanation of what a person is supposed to do with it.

The working model does not ask a returning decision-maker to review the Operating Fabric Dreamboard, learn the seven-aperture architecture, understand the Street Glide provider state machine, or inspect the Essential Attention case runtime before making a useful move. It starts with one concrete problem and shows the common operating grammar directly:

`signal → source → authority → safe action → fallback → closure → learning`

Four representative cases exercise that grammar: wildfire assistance, tools and time, mobility, and continuity. Each case states the prepared output and the consequence the model may not manufacture.

## The five-pilot gate

The surface compresses the remaining organizational dependency into five explicit decisions:

1. choose one real problem;
2. name the accountable sponsor;
3. assign and fund the continuity operator;
4. name the venue, resources, and field partners;
5. set the external-effect boundary and stop conditions.

The local pilot form preserves every blank as `UNRESOLVED` and exports a `manzanita-works/bounded-pilot-preparation@1` JSON packet. A complete-looking packet still carries `external_effect: none`; it cannot contact, schedule, assign, spend, enroll, inspect, publish, represent, authorize work, accept institutional scope, or release a field pilot.

## Existing surfaces remain authoritative for their own scope

The working model links rather than collapses the mature estate:

- `manzanita/` is the released public-safe Place Fabric, with seven apertures, eight selectable conditions, five operating seats, source state, action, acceptance, and handoff.
- `essential-attention/` is the local-first administrative case runtime, currently carrying the FAB aftermath as bounded records, decisions, source receipts, effect firewall, replay, and portable handoff.
- `manzanita-works/` is the deeper Operating Fabric architecture index.
- `manzanita-next/street-glide/`, `roles/`, and `experience/` remain separately governed internal candidates with their own release and authority boundaries.

The working model does not supersede those contracts and it does not upgrade an internal candidate to released standing.

## Governing invariants

Silence does not create consent, assignment, rejection, or completion. Capability and proximity do not assign the nearest person. Evidence visibility does not grant authority. Assistance and place evidence cannot become punitive standing. Affected actors retain correction, refusal, narrowing, deferral, acceptance, and appeal where applicable. Replaceable services may perform jobs without becoming the canonical institutional record. Continuity must live in records, receipts, replay, and a bounded operating seat rather than in one person's memory.

## Candidate boundary

The candidate contains no private participant record, field case, provider credential, telemetry, model call, payment adapter, email adapter, calendar adapter, or source-system writeback. It makes no runtime external API request. The only navigation leaves the page when a user deliberately opens an existing Manzanita surface.

Repository and browser qualification can establish only the candidate bytes and behavior. It cannot establish Manzanita Works institutional adoption, a funded operator, a pilot venue, resource commitment, participant consent, field authority, completed work, or public-release authority.

## Qualification

`tests/public_contract_test.py` verifies the exact candidate vocabulary, source links, scenario count, seven-stage grammar, five-pilot gate, pilot-export authority fields, network boundary, privacy boundary, accessibility hooks, and absence of personalized names.

`tests/browser_test.py` runs the candidate through Chromium. It verifies all four scenario projections, keyboard tab navigation, generated incomplete and complete preparation packets, `UNRESOLVED` preservation, no-effect authority fields, local draft persistence and clearing, theme persistence, ordinary mobile layout, 320-pixel layout at 200 percent text, reduced motion, and zero unexpected requests beyond the local test server.

The candidate workflow publishes screenshots and generated pilot packets as review artifacts only. It does not deploy the route.
