# Adapter admission and ownership

A Workbench adapter maps an already executable native workflow into a bounded local qualification and an explicitly scoped report. It does not translate away the native evidence format or invent a new signature scheme. Genesis and Knowledge Pack retain their existing identity/signing ownership. Each published Workbench distribution carries its exact donor ZIPs and source addresses.

## Contract

A donor entry names id, archive path, fixed extracted root, original repository path and revision, archive SHA-256, evidence class and limits. `RUNNERS` in proof.py is the reviewed allowlist. A new engagement record can select an admitted adapter; it cannot introduce executable commands, unreviewed URLs, tokens or import paths. The adapter returns a terminal PASS/FAIL, named counters with denominators, exact command receipts and original native report paths. A timeout, missing report, source mismatch or exception retains its failure and prevents aggregate PASS. Other independent admitted adapters still run.

## New workflow procedure

Recover the owning implementation and its exact accepted source. Identify native intake, correction, qualification, export and replay commands. Retain a frozen source distribution and original negative controls. Define explicit input mapping and acceptance before customer data enters the run. Add a bounded adapter, tests of status interpretation and missing output, and a recipient cold-run exercise. Refresh donor-map, build, verify determinism, execute on another host and inspect the browser delivery path. Record the versioned acceptance before publication. Three renamed examples over one formula do not qualify three domains.

## Customer work

The packaged qualify command deliberately executes retained reference fixtures. Customer exports use the relevant native kit under a separately reviewed mapping and permission. The engagement builder produces that proposed scope; it does not automatically convert arbitrary customer inputs or silently execute them. Integrating a second i3X endpoint, a live ERP, real scheduling identity or notification delivery requires its own adapter/data-authority acceptance. Changes to input truth, legal authority and production conditions stay distinct from source-integrity checks.

## Reusable evidence

Each local run owns its source extracts, stdout, stderr, native reports, timing and file manifest. Preserve old failed attempts. A new run gets a new directory; a transport interruption calls for inspecting the retained job, not replaying effects under a fresh identity. Stored PASS is an attributed result. Independent replay makes another observation. Recipient acceptance is a separate decision by the recorded owner.
