# MARY Local Workbench 0.3.0

**Build a local work environment whose context, work and results belong to you.**

[Download the build kit](MARY-Local-0.3.0.zip) · [Build and operating guide](BUILD.md) · [Acceptance and limits](ACCEPTANCE.json) · [Source provenance](SOURCE-PROVENANCE.json)

Extract the ZIP. On Windows, open `Install.cmd`. On Linux or macOS, run `sh Install.sh`. The installer supplies a pinned managed Python and verified application packages; it requires no Git, cloud API key, subscription or administrator rights. Read the guide before running a downloaded installer. The final three-platform run is recorded in `CI-ACCEPTANCE.json` when available.

Add selected files or a specific folder. Connect an existing ODS, llama.cpp or Ollama local endpoint, or choose **Prepare local CPU worker**. Qualify that worker, then request source-grounded answers, drafts, comparisons, exact calculations or table analysis. Exact tools and source custody work without a language model.

The installed path uses **AXM Core / Forge → Genesis verification → Spectra → MARY work → Genesis-sealed outcomes**. Sources, current versions, task intent, permission boundaries, checkpoints and useful artifacts live in the local workspace. The model receives relevant context and selects semantic evidence; deterministic software supplies exact source text, computation and execution checks.

The build has an actual Windows 11 recipient installation, an actual NUC6i7KYK Linux installation, a real CPU model-to-artifact run, browser acceptance and encrypted context restoration. GPU-runtime acceptance stays separate: the observed NUC has an **MI100 over Thunderbolt**, and an **MI50 profile still requires its own commissioning**. The application connects to a compatible local endpoint without changing drivers or GPU controls.

This is a single-owner release, with explicit limits in the guide and acceptance record. Interpretation remains human-reviewed; cryptographic integrity does not make prose true. New model/task/hardware combinations receive their own evidence rather than inheriting a blanket qualified label.

Code, dependencies and installer instructions remain inspectable. The selected owner-authored snapshot is Apache-2.0; upstream packages and model weights retain their own terms. Your private records and keys are not part of this public repository.
